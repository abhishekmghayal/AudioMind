 # AudioIntelligence

A prototype that analyzes speech and environmental sounds together and answers
questions using evidence from the recording.

Built on pretrained models: **Faster-Whisper** (speech) and
**Audio Spectrogram Transformer, AST** (sound events). No model was trained
for this project.

## What it does

1. Upload an audio file (WAV, MP3, FLAC, OGG, M4A)
2. Convert it to mono 16 kHz audio (FFmpeg)
3. Transcribe speech with timestamps (Faster-Whisper)
4. Detect sounds in sliding 3 s windows (AST), with speech classes removed
5. Fuse both into one timeline, and rate sounds as strong, likely or weak
6. Answer questions from that evidence, or say when evidence is insufficient

## Requirements

- macOS or Linux
- Python 3.12 (3.14 may lack wheels for some ML packages)
- FFmpeg installed and on PATH (`ffmpeg -version`)
- Internet on first run to download models (about 140 MB to 460 MB for
  Whisper, about 350 MB for AST)

## Setup

```bash
cd ~/AudioIntelligence
source .venv/bin/activate
uv pip install -r requirements.txt
```

## Run the app

```bash
streamlit run app.py
```

Then open the URL shown in the terminal (usually http://localhost:8501).
Upload a file, choose a speech model and language, click **Analyze**, and use
the Transcript, Sounds, and Ask a question tabs.

## Run from the terminal

```bash
python -m tests.test_pipeline data/sample_audio/mixed1.m4a
```

The result is saved to `outputs/<name>_analysis.json`.

## Run the tests

```bash
python -m tests.test_audio
python -m tests.test_fusion
python -m tests.test_gaps
python -m tests.test_qa
```

`tests.test_qa` reads `outputs/audio2_analysis.json`, so run the pipeline on
`audio2.m4a` first.

## Example questions

- What was said?
- Was there a siren?
- What sounds were heard when the speaker said explosions?
- What was happening at 10 seconds?
- How reliable is this?

## Implemented

- Audio validation and conversion
- Speech transcription with timestamps and language detection
- Sound detection in windows, with persistence-based confidence levels
- Speech and sound alignment by time
- Rule-based question answering with insufficient-evidence replies

## Limitations

- Pretrained models only; no training or fine-tuning was done.
- Question answering is keyword-based and English only.
- Sound timestamps are window-level, not exact event onsets.
- Scores are model outputs, not calibrated probabilities.
- Loud background sounds reduce transcript accuracy.
- Quiet sounds under speech can be missed.
- Detection in pauses between speech is implemented but has not been
  validated on a real recording.
- No formal evaluation (WER, sound F1) has been done yet.
